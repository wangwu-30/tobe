> - 核心原则：**展示层 ≠ 存储层**，用户只接触展示层

## P1 严重

### [P1-1] 渲染：文档内容展示原始 Markdown 源码

**位置**：工作区 > 中央内容区域 > 文档类项目
**现状**：进入 "Write a product release note" 等文档类工作区后，中央编辑区直接展示 `## TL;DR`、`---`、`**Release Date:**`、`### Real-Time Collaborative Boards` 等原始 Markdown 语法。用户看到的是"协议层"而非"结果层"。
**预期**：内容应始终以渲染后的富文本形式呈现（标题有样式、分隔线有视觉、粗体有加粗），用户任何时候看到的都是"成品"而非"草稿源码"。
**影响**：违背核心产品目标 "AI 原生写作"——用户不应该需要理解 Markdown 语法才能阅读自己的内容。
**截图**：

![文档内容显示原始Markdown](/Users/wangwu/.gemini/antigravity/brain/2f6652fc-11a9-4b11-9a17-e9ef588005f3/workspace_main_content_audit_1774301554633.png)

**建议**：
- 文档类内容默认使用 Plate 富文本编辑器渲染（项目中已有 Plate 集成）
- 仅在用户主动选择"源码模式"时展示原始 Markdown
- 这是当前产品体验的最大落差点

---

### [P1-2] 渲染：Web 项目展示原始 JSX 源码而非渲染结果

**位置**：工作区 > 中央内容区域 > Web 类项目（如 "A beautiful landing page..."）
**现状**：进入 Web 类工作区后，中央区域显示的是原始 JSX/React 源码（`import React from "react"; export default function DaoCoffeeLanding()...`），而非渲染后的网页预览。用户看到的是代码编辑器，不是网页结果。
**预期**：Web 类项目应默认展示 iframe 预览结果（渲染后的网页），源码作为"实现"面板在需要时展开。当前 iteration-regression-plan 已明确要求："打开 web 交付物时，中央主表面始终停留在对应的结果壳里，不会默认回退到 Markdown / 实现源码"。
**影响**：用户创建 "landing page" 但看到的是代码，完全背离了"成形"产品的"先看结果"理念。
**截图**：

![Web项目显示原始JSX代码](/Users/wangwu/.gemini/antigravity/brain/2f6652fc-11a9-4b11-9a17-e9ef588005f3/.system_generated/click_feedback/click_feedback_1774301754463.png)

**建议**：
- 确保 Web 类型交付物进入时自动启动 preview 并切换到结果面
- 如果 preview 未就绪，显示加载态引导而非直接露出源码

### [P1-3] 信息架构：工作区侧栏被全局项目列表淹没

**位置**：工作区 > 左侧栏
**现状**：进入工作区后，左侧栏上半部分仍被全局项目列表（15+ 个项目）占据。核心的工作区工具——"项目内定位"（搜索）、"目录"（节点树）、"大纲"（文档结构）、"关联项目"——全部被压在首屏以下，需要大量滚动才能看到。
**预期**：进入工作区后，侧栏应优先展示**当前项目上下文**的导航工具（大纲、文件树、搜索），全局项目列表应收纳在折叠区域或二级菜单中。设计原则要求 "首扫线显示当前对象 + 当前状态 + 下一步操作"。
**影响**：用户在长文档中需要跳转到特定章节时，要先滚过一长串不相关的项目列表才能找到大纲。这增加了认知负担，违背了 Occam 原则。
**截图**：

![侧栏滚动后才看到大纲](/Users/wangwu/.gemini/antigravity/brain/2f6652fc-11a9-4b11-9a17-e9ef588005f3/sidebar_scrolled_2_1774300876548.png)

**建议**：
- 工作区内侧栏分两段：上半 = 当前项目工具（大纲/目录/搜索），下半 = 可折叠的全局项目列表
- 或改为标签页切换："当前项目" vs "全部项目"

### [P1-4] 信息架构：首页项目卡片操作语义不清

**位置**：首页 > 项目卡片 > "继续当前内容" / "继续下一项内容"
**现状**：每张项目卡片底部有两个操作按钮——"继续当前内容 →" 和 "继续下一项内容 +"。用户反馈："什么叫继续当前内容、继续下一项内容，很难理解啊"。
  - "当前内容"指什么？卡片本身就是项目，项目下有 node，"当前"指哪个 node？
  - "下一项内容"是创建新 node？还是打开项目的下一个交付物？
  - 两个按钮的区别不直觉
**预期**：操作标签应直接表达意图，例如：
  - "打开项目" / "进入工作区"（替代"继续当前内容"）
  - "新建内容" / "添加交付物"（替代"继续下一项内容"）
  - 或者卡片只保留一个主操作（点击进入），通过 hover 或更多菜单暴露次要操作
**影响**：首页是用户的第一触点，操作语义不清会造成犹豫和误操作。

## P2 中等

### [P2-1] 交互：折叠侧栏的项目列表完全丧失可读性

**位置**：全局 > 左侧栏 > 折叠状态
**现状**：折叠后所有项目显示为完全相同的文件夹图标（`FileText` icon），无任何区分度。用户无法识别哪个图标对应哪个项目。
**预期**：两种方案（用户原话）：
  - 要么不展示：折叠后隐藏项目列表，只保留核心功能入口（新建、设置）
  - 要么展示有意义的东西：用项目首字母、颜色标识、或 AI 生成的标志来区分
**影响**：折叠功能沦为摆设——折叠后无法切换项目，只能重新展开。

---

### [P2-2] 布局：版本控制栏控件过于密集

**位置**：工作区 > 顶部版本控制栏
**现状**：一行内堆叠了 "已保存里程碑"、"评论"、草稿选择器、"比较"、"版本树"、"正式里程碑 1"、"已 Pin 回退 1/3"、"最近临时位 1"、"保存里程碑" 共 8+ 个控件。层级不明，高频/低频操作并列。
**预期**：
  - 高频：当前状态标签 + 保存里程碑 → 保留在首行
  - 中频：比较、版本树 → 保留但视觉降级
  - 低频：Pin 数量、临时位数量 → 收入更多菜单或 hover 展示
**影响**：视觉压力大，新用户不知道从哪看起。

---

### [P2-3] 信息架构：首页卡片 "最近活跃内容" 重复项目名

**位置**：首页 > 项目卡片 > "最近活跃内容" 区块
**现状**：卡片标题已经是 "Write a product release note"，卡片内部还有一个 "最近活跃内容" header 下面再次显示 "Write a product release note"。对于只有一个 node 的项目（大多数），这完全是重复信息。
**预期**：
  - 单 node 项目：不需要"最近活跃内容"区块，直接用卡片标题即可
  - 多 node 项目：只显示与卡片标题不同的 node 名称
**影响**：增加视觉噪音，降低信息密度的有效性。

---

### [P2-4] 渲染：副标题 "AI 原生创作工作台" 对比度不足

**位置**：侧栏 > 顶部 logo 下方
**现状**：`text-xs text-muted-foreground` 让副标题几乎不可见，品牌信息传达不够。
**预期**：适当提高对比度或字号，让品牌定位在第一眼可见。
**影响**：品牌识别度降低。

---

### [P2-5] 交互：折叠侧栏后工作区大纲/搜索完全不可用

**位置**：工作区 > 左侧栏 > 折叠状态
**现状**：用户折叠侧栏以获得更多写作空间后，文档大纲、项目内搜索等导航工具随之完全消失，没有替代性的悬浮图标或快捷键入口。
**预期**：折叠状态下保留大纲和搜索的 icon 入口，点击后以 popover 或 drawer 形式展开，类似 VS Code 的 Activity Bar。
**影响**：用户在"专注模式"下失去了结构化导航能力。

---

### [P2-6] 布局：侧栏底部"设置"与项目列表缺乏视觉分隔

**位置**：侧栏 > 底部 "设置" 按钮
**现状**：设置按钮紧贴项目列表底部，没有明显的分隔线、间距或背景差异。滚动时容易和项目列表混为一谈。
**预期**：设置按钮应该有 sticky 定位或 border-top 分隔，始终可见在侧栏底部。
**影响**：用户可能需要滚动到底才发现设置入口。

## P3 轻微

### [P3-1] 信息架构：侧栏项目副标题 "X 项内容" 术语模糊

**位置**：侧栏 > 项目列表 > 每个项目下方
**现状**：显示 "继续当前内容 · 1 项内容 · 最近：Write a product..."，其中 "1 项内容" 的"内容"一词过于泛化。
**预期**：使用与内部模型一致的术语，如 "1 个节点" 或简化为 "1 份交付物"。
**影响**：轻微的术语不一致。

---

### [P3-2] 渲染：首页 hero 区 "AI 原生写作" 标签字号过小

**位置**：首页 > hero 区域 > "AI 原生写作" 标签
**现状**：`text-sm text-muted-foreground` 样式让这个标签在整个 hero 区几乎被忽略。
**预期**：作为产品定位标识，可以适当增大或使用品牌色。
**影响**：品牌定位信息不够醒目。

---

### [P3-3] 交互：首页顶栏副标题 "从目标开始，而不是从空白文件开始" 可精简

**位置**：首页 > 顶栏 > 面包屑副标题
**现状**：副标题过长，在顶栏有限空间内占据了过多水平空间。
**预期**：精简为 "目标驱动创作" 或仅保留 "首页"，长 slogan 放在 hero 区。
**影响**：顶栏视觉密度略高。

---

### [P3-4] 一致性：项目卡片日期显示 "昨天" 而非具体日期

**位置**：首页 > 项目卡片 > 右上角时间标签
**现状**：所有卡片显示"昨天"，使用相对时间。
**预期**：相对时间本身没错，但当所有卡片都显示相同的"昨天"时，这个信息就失去了区分价值。可考虑只在时间有实质差异时显示。
**影响**：信息冗余，视觉噪音轻微。
