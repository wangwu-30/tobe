# ADR：成形商业模型——三层订阅 + Workflow 云端运行 + 贡献返额度

> 变更类型：商业方向 ADR
> 日期：2026-03-23
> 状态：讨论稿
> 关联：[内容生态愿景](./content-ecosystem-vision.md) · [迭代路线](./iteration-roadmap.md) · [北极星](../chengxing-product-north-star.md)

---

## 现状

- 成形是本地 Electron 应用，用户自带 API key，没有云端、账号体系和收费基础设施。
- Playbook / Workflow / Note 全部存在本地，无法流通。
- [内容生态愿景](./content-ecosystem-vision.md) 已确认"卖结果不卖时间"方向，但缺乏具体变现路径。
- Phase 13（云端）、Phase 16（AI 运行时）尚未启动。

---

## 目标

建立可持续的商业模型，满足三个约束：

1. **免费层足够好**——让用户充分体验产品价值，不靠功能残缺逼付费。
2. **生态有真实经济激励**——贡献者的方法论资产能带来持续回报，不只是"为爱发电"。
3. **方法论流通但不泄露**——使用者用到好方法，贡献者不会失去壁垒。

---

## 核心决策

### 决策 1：三层订阅

| 层级 | 价格 | 核心卖点 |
|------|------|---------|
| **免费** | ¥0 | 本地全功能 + 自带 API key |
| **标准** | ~¥39/月 | 云端同步 + 分享 + 调用别人的 Workflow + 轻量官方模型额度 |
| **专业** | ~¥149/月 | 高额模型额度 + 发布 Workflow + Agent 服务能力 |

免费层不限制核心功能，只限制"网络效应"：云端同步、分享链接、生态参与。用户在本地建立依赖后，对分享和复用的需求自然驱动付费。

### 决策 2：Workflow 云端运行，不分享到本地

这是本 ADR 的关键决策。

贡献者发布的 Workflow 存储在云端，使用者只能**调用**，不能**下载**：

```
使用者提交 Brief → 云端加载贡献者的 Workflow → 模型执行 → 返回 Result
使用者拿到结果，看不到方法细节
```

使用者在市场里看到的是：说明、评分、示例产出、预估消耗。看不到：步骤、约束、prompt、骨架。

#### 为什么不分享到本地

| | 分享到本地 | 云端运行 |
|---|---|---|
| 贡献者壁垒 | ❌ 复制即失去 | ✅ 方法不可见 |
| 使用者体验 | 拿到文本自己配 | 一键调用拿结果 |
| 贡献者迭代 | 更新不同步 | 更新即刻生效 |
| 计量精度 | 按 fork 次数估 | 按 token 消耗精确计 |
| 平台控制力 | 低 | 高（可审计、可计费） |

#### 与协议层的映射

| 协议原语 | 在 Workflow 云端运行中的角色 |
|---------|---------------------------|
| Brief | 使用者提交的目标 + 约束 + 上下文 |
| Result | 云端执行返回的交付物（State + Files） |
| Review | 使用者对结果的评论、修改请求 |

#### 对 SYSTEM.md 的影响

`Method` 对象需新增 `visibility` 字段：

- `private` — 只有作者可见可用
- `listed` — 市场可见，云端调用（方法内容不暴露）
- `published` — 市场可见 + 作者选择公开全部内容（教学场景）

### 决策 3：贡献者按次返额度

贡献者的 Workflow 每被调用一次，按实际模型消耗的一定比例返还额度到贡献者账户。

#### 一次调用的成本分解

```
模型 token 成本       $0.05   → 模型提供商
平台费               $0.02   → 成形利润（纯利）
贡献者返利            $0.01   → Workflow 作者额度
──────────────────────────
使用者支付            $0.08   → 从额度扣除
```

#### 返利比例建议（按月被使用次数递减）

| 月使用次数 | 返利比例 | 逻辑 |
|-----------|---------|------|
| 0–100 | 15% | 冷启动激励 |
| 100–1,000 | 10% | 常规 |
| 1,000+ | 5% | 控制头部成本 |

#### 防刷规则

- 仅付费用户的使用产生返利
- 同一用户对同一 Workflow 每天最多计 1 次
- 返利基于实际 token 消耗，非点击次数
- 额度 90 天有效期，最高累积上限 ¥500

#### 为什么优于"超阈值免费订阅"

- 粒度细：每次使用都有即时反馈
- 财务可控：不会因触发阈值一次性承担整月成本
- 不易被 game：刷一次只赚 $0.01，不值得
- 心态更好："我的知识在持续产生收益" vs "我在攒免费资格"

## 差距

1. **基础设施**：三层模型全部依赖 Phase 13（云端）完成。Workflow 云端运行还需要沙箱 worker（可复用 Phase 13.4 的预览容器化）。
2. **生态冷启动**：市场上线时需要官方 Workflow 模板填充初始内容。
3. **模型差价不是利润中心**：重度用户模型成本可能高于订阅收入，平台费（每次 Workflow 调用的抽成）才是真正可持续的利润来源。
4. **定价验证**：¥39/¥149 需要通过早期用户测试验证价格敏感度。

## 执行计划

```
Phase 13 之前：
  全部免费，积累用户和口碑
  不建设任何收费基础设施

Phase 13 完成（云端就绪）：
  开放标准订阅（云端同步 + 分享）
  轻量官方模型额度作为体验入口

Phase 15–16 完成（生态 + AI 运行时）：
  Workflow 市场上线（云端运行模式）
  贡献返额度机制上线
  开放专业订阅（Agent 服务能力 + 高额模型）

远期：
  Agent 服务平台（Brief → Result → Review）
  贡献者从"返额度"升级为"返收入"
  平台抽佣 + 订阅混合模式
```

---

## 验收标准

- 本文档是方向 ADR，当前无开发交付要求。
- 后续设计决策需要满足：
  - 不引入 Workflow 与本地存储深度耦合的反模式（为云端运行留空间）
  - Method 对象保持可序列化、可远端执行
  - 模型调用走统一端点，便于后续加计量层
