# 开放内容生态愿景：从卖时间到卖结果

> 变更类型：远景方向
> 日期：2026-03-22
> 状态：方向已收敛，待进一步设计

---

## 现状

### 当前互联网的劳动力模型

一个设计师一天能做 2 个方案，服务上限 = 时间 × 1。
一个咨询顾问一周能服务 1 个客户，收入上限 = 时薪 × 工时。

个人的专业经验、审美标准、方法论，全部锁死在大脑里，只能通过"本人在场、逐小时输出"变现。

### AI 正在改变的事

AI 模型能力正在被拉平（开源追上闭源）。模型本身不再是壁垒。

**真正稀缺的是：调教 AI 的经验。** 你花三天和 AI 反复迭代、评论修正、沉淀 Playbook 和 Note，最终让 AI 能稳定按你的标准输出——这套"认知资产"在当前互联网上完全没有流通能力，锁在本地应用进程里。

### 为什么"分享 Playbook"不是正确路径

方法一旦公开分享，创作者就失去壁垒。这不符合经济激励。
Playbook 是个人 Agent 的核心资产，**是用来服务客户的，不是用来分发的。**

---

## 目标

### 劳动力模型的范式变革

```
旧世界：卖时间
  设计师 → 1天做2个方案 → 服务1个客户

新世界：卖结果
  设计师 → 经验沉淀为 Agent → Agent 7×24 同时服务 50 个客户
  → 只有 Agent 搞不定时，设计师才介入（HITL）
  → HITL 是成本，不是功能；Agent 越强，利润率越高
```

每个人的成形实例就是他的"公司"：

- **培养阶段**：用户在成形里创作 → 和 AI 反复迭代 → 评论修正 → 沉淀 Playbook 和 Note → Agent 越来越懂用户标准
- **服务阶段**：Agent 接收外部客户的 brief → 按沉淀方法论自主交付 → 只在关键节点通知用户决策
- **飞轮**：服务越多客户 → 暴露越多边界情况 → 用户介入修正 → Agent 学到更多 → 更少需要介入

### 类比：Claude Code 的三个缺陷，就是成形要解决的问题

Claude Code 已经是一个超级 Agent 原型：接收 brief、理解上下文、产出代码和文档、用户评审、迭代。但它有三个致命缺陷：

1. **没有持久记忆**。每次对话从零开始，调教成果无法跨 session 保留。
2. **不能同时服务多个客户**。只能 1:1。
3. **交付物没有标准格式**。改完文件就算交付了，没有版本、没有评审面、不可追溯。

**成形 = 解决了这三个缺陷的 Agent 操作系统。**

## 协议层：极薄

协议不管 Agent 内部怎么运行、用什么模型、Playbook 长什么样、怎么定价、要不要 HITL。

协议只定义三个原语：

| 原语 | 说明 |
|------|------|
| **Brief** | 标准化的目标 + 约束 + 参考上下文 |
| **Result** | 标准化的交付物格式：内容 + 版本 + 可评审表面 |
| **Review** | 标准化的评论 / 修正反馈 |

三个动词，三个名词。就这么多。

- 定价是业务层，不是协议层（HTTP 不管网站卖订阅还是卖广告）。
- HITL 是 Agent 主人自己的成本结构，客户不关心。
- 供给侧可以是成形，也可以不是成形。需求侧可以是任何界面。

---

## 成形的定位

**成形的使命是打破这个窗口，定义协议，做第一个完整实现。**

- 成形是 reference implementation，不是垄断生态的终点。
- 如果未来成形落后了，被淘汰是自然的。协议活下来就够了。
- 类比：Tim Berners-Lee 造了第一个浏览器，也定义了 HTTP/HTML。浏览器早被取代了，协议活了 35 年。

### 成形现有模型与协议的天然映射

| 协议概念 | 成形现有模型 |
|---------|------------|
| Brief | Goal + constraints |
| Plan | Plan + Steps |
| Result | State + Files + RenderAdapter |
| Review | Thread + Comment |
| HITL 触发 | Action status = `needs_confirmation` |

成形的内部对象模型，天然就是协议的草稿。内部跑通了，协议自然从里面长出来。

---

## 推进路径

1. **当前**：把成形内部模型跑通跑稳（创作→迭代→评审→沉淀的完整闭环）
2. **中期**：增加 Agent 自主服务能力（接收外部 brief、自主交付、HITL 路由）
3. **远期**：提炼协议规范，开源发布，让任何平台都能实现兼容的 Agent 服务节点
