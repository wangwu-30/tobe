## 现状

### 成形当前能做什么

成形是一个以交付物为中心的 AI 创作工作台：
- 用户说目标 -> AI 生成计划 -> AI 起草 -> 用户评论修正 -> 迭代
- 支持 `document | web | slides` 三种交付物类型
- 有完整的评论、版本、分支、Playbook、Status 机制

### 成形当前不能做什么

- 不能打开任意网页浏览
- 不能在外部网站上操作（填表、下单、采集信息）
- 不能让 AI 替用户执行网页上的任务
- agent 能力只服务于"创作"场景

### 已经具备的基础

- 通用 agent loop（Context + ToolKit + Persona + Policy + RenderAdapter）
- agent 自动操作浏览器的能力（已有）
- web 预览 bridge 机制（iframe 注入 JS 实现选区评论）
- 可插拔的 ToolKit 和可扩展的 RenderAdapter

---

## 目标

**成形要成为用户在 Agent 世界的统一入口。**

用户在成形里可以完成任何数字任务：创作文档、做网站、浏览网页、操作网站、自动化重复任务、监控变化。AI 是执行者，用户是掌控者。

## 差距

### 不需要变的（已有能力直接复用）

| 已有机制 | 在统一入口里的作用 |
|----------|-------------------|
| agent loop | 通用执行引擎，不分创作/操作 |
| Plan + Steps | AI 拆解任何任务的步骤 |
| Status 面板 | 显示 AI 进行到哪一步 |
| 评论系统 | 用户对 AI 操作的修正反馈 |
| 版本/状态快照 | 每步操作的回退点 |
| Playbook | 把成功操作流程沉淀为可复用方法 |
| Context / Note | 记住用户偏好和常用信息 |

### 需要新增的

| 新增项 | 说明 |
|--------|------|
| `renderAs = 'browser'` | 新的画布类型：浏览器视图 |
| Browser RenderAdapter | 文件契约=截图/操作日志；预览=实时网页；anchor=DOM 元素；diff=截图对比 |
| Browser ToolKit | `browse / click / type / screenshot / extract / evaluate` |
| Electron webview 容器 | 中央主表面嵌入真实浏览器 |
| 操作录制 | 记录用户/AI 的操作序列，支持回放和沉淀为 Playbook |
| session 管理 | 保持网站登录态，支持多账号 |

### 交付物模型的泛化

当前交付物 = 用户创造出来的内容（文档、网站、PPT）。

泛化后交付物 = 用户想要达成的任何结果：

| 创作交付物 | 操作交付物 |
|-----------|-----------|
| 一份文档 | 填好的表格 |
| 一个网站 | 在某平台完成的操作 |
| 一份 PPT | 从多个网站收集的数据 |
| - | 定期监控某网站的变化报告 |

数据模型不变：Goal - Plan - Steps - Files - State。Files 的内容从"源码/文档"扩展到"截图/操作日志/提取数据"。

## Human-AI-Friendly 设计原则

这是成形统一入口和纯自动化工具的核心区别。

| 原则 | 创作场景（已实现） | 操作场景（同理复用） |
|------|-------------------|---------------------|
| 共屏协作 | 编辑器里看 AI 写内容 | 浏览器里看 AI 点击、输入、滚动 |
| 随时接管 | 用户随时编辑草稿 | 用户随时暂停 AI、自己操作网页 |
| 可评论 | 评论系统反馈修改 | 在 AI 操作步骤上评论"应该点这个" |
| 可回溯 | 版本树回到任何版本 | 操作序列回到任何一步 |
| 可沉淀 | Workflow Playbook | 操作流程沉淀为可复用自动化 |
| 透明度 | Status 面板 | "正在第 3 步：在搜索框输入关键词" |

## 网页增强层

浏览器画布 + bridge 注入构成一个通用的网页增强平台。翻译只是增强能力之一：

| 增强能力 | 原理 | 场景 |
|----------|------|------|
| 评论/标注 | 注入评论层 | 对任何网页画词评论，下次再访时回显 |
| 沉浸式翻译 | 注入语言层 | AI 双语对照翻译，可评论修正，偏好可沉淀 |
| 信息提取 | 注入采集层 | 自动提取结构化数据存为支持资料 |
| 高亮/标记 | 注入高亮层 | 研究时标记重点，关联到项目 |
| 简化阅读 | 注入排版层 | 去广告、简化布局、专注模式 |

### 评论持久化与回显

用户对某个 URL 画词评论后，下次重新打开同一 URL，评论自动回显：

```
第一次浏览 notion.so/pricing：
  选中 "Pro plan $10/月" → 评论 "比我们便宜"
  保存：URL + anchor(selector + text) + DOM snapshot + 截图片段

一周后再次打开：
  匹配 URL → 找到评论线程 → bridge 重新定位锚点 → 高亮并显示气泡
  如果页面改版 → 标记"锚点已漂移" → 让用户决定更新或保留
```

复用现有 web 交付物的跨版本评论锚点重定位机制，从"自己的交付物"扩展到"任意 URL"。

### 成形级翻译 vs 传统翻译插件

| 维度 | 沉浸式翻译等插件 | 成形翻译 |
|------|-----------------|---------|
| 翻译引擎 | 固定引擎 | 用户选择的 AI 模型 |
| 上下文 | 无 | Context/Note 知道用户的领域术语偏好 |
| 反馈闭环 | 不支持 | 可评论 → AI 修正 → 翻译偏好沉淀为 Note |
| 结果保存 | 只在当前看 | 翻译可保存为支持资料，后续直接引用 |
| 集成度 | 独立插件 | 原生功能，和创作闭环打通 |

## 本地知识采集

浏览器画布不只是"看网页"，是**用户知识的采集入口**。

### 采集流程

```
浏览 → 标注/评论 → 自动提取 → Note(Knowledge) → AI 在创作时自动引用

1. 用户在某篇文章上高亮了 3 段话
2. 系统自动：
   - 保存原文 + 来源 URL + 时间戳 → 支持资料（防止网页消失）
   - 提取核心观点 → Note(scope=user, kind=knowledge)
   - 保留原文锚点 → sourceRef 指回 URL + 选区
3. 用户在成形里写相关文档时：
   - AI 从 Context 里找到这些 Note
   - 自动引用："根据你之前在 xxx.com 上标注的内容..."
   - 引用可一键跳回原始网页的精确位置
```

### 现有模型映射

| 现有模型 | 在知识采集里的角色 |
|----------|-------------------|
| `Note scope=user` | 用户级知识，跨项目可复用 |
| `Note scope=project` | 某个项目的参考资料 |
| `Note sourceRef` | 指回原始 URL + DOM 锚点 |
| 支持资料 File | 保存原文快照（防网页不可用） |

### 核心价值

**浏览器是知识采集端，创作台是知识应用端，Note 是中间层。**

用户日常刷网页的过程本身就在积累 AI 可用的知识库，不需要手动整理。AI 在创作时自动找到并引用这些知识，形成"浏览即学习，创作即应用"的闭环。

## 用户场景示例

### 场景 1：竞品研究

```
用户：帮我分析 Notion、Coda、Gamma 三个产品的定价页面

AI 执行过程（用户全程在浏览器画布上看到）：
1. 打开 notion.so/pricing → 截图 + 提取定价表
2. 打开 coda.io/pricing → 同上
3. 打开 gamma.app/pricing → 同上
4. 在支持资料里生成竞品定价对比表
5. 在当前文档交付物里插入分析章节

用户可以：
- 在 AI 浏览某个页面时说"往下滚，还有企业版定价"
- 在 AI 提取的数据上评论"这个价格不对，是年付价格"
- 把这套流程沉淀为"竞品定价分析"Playbook
```

### 场景 2：表单填写

```
用户：帮我在政务网站上填写这份申请

AI 执行过程：
1. 打开目标 URL → 用户看到网页
2. AI 读取表单字段 → 展示 Plan："第 1 步填个人信息，第 2 步填申请内容..."
3. AI 从 Context / Note 里找到用户常用信息（姓名、地址等）
4. AI 逐步填写 → 用户在浏览器画布上实时看到
5. 到敏感字段（如身份证号）→ AI 暂停，等用户手动输入
6. 填写完成 → AI 截图确认 → 等用户说"提交"

用户可以：
- 随时修改 AI 填的内容
- 对某个字段说"以后都填这个值" → 存入 Note
- 把这套流程沉淀为"XX申请填写"Playbook，下次自动复用
```

### 场景 3：定期监控

```
用户：每天早上帮我检查这 3 个网站有没有更新

AI 自动化过程：
1. 按 Playbook 打开 3 个 URL
2. 截图 + 和上次的截图对比
3. 提取变化内容
4. 在成形里生成变化报告（支持资料）
5. 如果有重大变化 → 通知用户

长期价值：
- 用户从不需要手动刷新这些网站
- 变化历史全部留在成形的版本系统里
```

### 场景 4：创作 + 浏览器闭环

```
用户正在成形里写一份文档，引用了一个网页

AI："你引用的这个数据源已经更新了，要不要看看？"
→ 浏览器画布打开该网页
→ 用户在网页上选中新数据 → 评论"用这个替换文档里的旧数据"
→ AI 在文档里自动更新引用

创作和浏览器无缝切换，不需要离开成形。
```

## 执行计划

### Phase B1：最小浏览器画布（3-4 天）

| 步骤 | 交付物 | 说明 |
|------|--------|------|
| B1.1 | `renderAs = 'browser'` 注册 | RenderAdapter + Canvas 骨架 |
| B1.2 | Electron webview 容器 | 中央主表面嵌入，URL 输入框 |
| B1.3 | 基础 bridge 注入 | 在任意网页上选中文本 -> 创建评论 |
| B1.4 | 截图 + DOM 摘要 | AI 可以"看到"网页 |

**退出条件**：用户在成形里输入 URL -> 看到网页 -> 选中文字 -> 创建评论。

### Phase B2：AI 操作浏览器（3-4 天）

| 步骤 | 交付物 | 说明 |
|------|--------|------|
| B2.1 | Browser ToolKit | browse/click/type/screenshot/extract |
| B2.2 | 共屏协作 | AI 操作时用户实时看到光标、高亮 |
| B2.3 | 操作暂停/接管 | 用户随时 pause AI、自己操作 |
| B2.4 | 操作历史 | 每步操作生成状态快照 |

**退出条件**：用户让 AI 在某网站上完成一个多步操作，全程可见可接管。

### Phase B3：Playbook 打通（2-3 天）

| 步骤 | 交付物 | 说明 |
|------|--------|------|
| B3.1 | 操作录制 | 用户/AI 的操作序列可导出为 Playbook |
| B3.2 | 操作回放 | 从 Playbook 自动执行操作 |
| B3.3 | 参数化 | Playbook 支持变量（如不同的搜索关键词） |

**退出条件**：用户操作一次 -> 沉淀为 Playbook -> 下次一键自动执行。

## 技术可行性

全部在本地 Electron 可完成，不需要云端：

| 能力 | 技术方案 | 依赖 |
|------|----------|------|
| 打开任意网页 | Electron webview | 无限制 |
| AI 读取网页 | webview.executeJavaScript + 截图 | 已有 agent 能力 |
| AI 操作网页 | webview.executeJavaScript 注入点击/输入 | 已有 agent 能力 |
| 用户在网页评论 | bridge 注入（复用 preview bridge） | 已有 |
| 操作录制 | 监听 webview 事件 | 新增 |
| session 管理 | webview partition | Electron 原生 |
| 离线缓存 | 截图 + DOM 保存到本地 | 已有文件系统 |

## 竞争定位

| 产品 | 定位 | 成形的差异 |
|------|------|-----------|
| Claude Computer Use | AI 操作你的电脑 | 成形：Human-AI 共屏协作，不是后台偷偷操作 |
| Operator / Devin | AI 自动执行任务 | 成形：可评论可修正可沉淀，不是一次性执行 |
| Arc / 浏览器 AI | 浏览器里加 AI | 成形：AI 是第一等公民，不是浏览器的插件 |
| Notion / 创作工具 | 只创作 | 成形：创作 + 操作统一 |

成形的独特价值：**不是把 AI 塞进浏览器，是把浏览器拉进 AI 工作台。** 用户的主界面是成形，浏览器是 AI 的一个工具。

## 风险与决策点

| 风险 | 应对 |
|------|------|
| webview 安全（恶意网页） | sandbox 隔离 + 权限控制 + 用户确认敏感操作 |
| 操作不稳定（DOM 变化） | Playbook 支持多种 selector 策略 + AI 自愈 |
| 用户信任（AI 操作账号） | 敏感操作必须经用户确认 + 操作全程可见可回退 |
| MVP 范围膨胀 | Phase B1 只做最小画布，验证价值后再推进 B2/B3 |
